Automated Documentation Sync

One Jira story. A governed path to pull request.

The SDLC orchestrator routes a user story through the required phases, calls the right Copilot agent, updates the matching delivery artifacts, and stops whenever a human approval or quality gate is required.

Start Here

Use a workspace slash command in GitHub Copilot Chat.

/start-sdlc PROJ-123

Or continue an existing delivery:

/resume-sdlc PROJ-123

If an authenticated Jira issue-read tool is available, the story is retrieved. Otherwise, Copilot asks you to paste it.

Orchestrator Route

The order is fixed. A later phase cannot begin until required deliverables and approvals exist.

01RequirementsClarify the Jira story
02ArchitectureDesign the solution
03Design ReviewResolve risks and gaps
04PlanOrder dependencies
05ImplementBuild approved work
06VerifyRun relevant checks
07ReviewAssess readiness
08Prepare PRPackage evidence

Who Does What

Each row shows the agent the orchestrator calls, what that role does, and the documentation it creates or updates.

1

Requirements

planner

Turns the Jira story into functional and non-functional requirements, acceptance criteria, assumptions, dependencies, and scope boundaries.

  • requirements.md
Human approval required before architecture.
2

Architecture

planner

Defines components, responsibilities, technology choices, document flow, trust boundaries, error handling, and operational concerns.

  • architecture.md
Human approval required before design review.
3

Design Review

design-reviewer

Finds architecture risks, security gaps, failure modes, and missing decisions; records owners and remediation before implementation begins.

  • design-review.md
  • architecture.md (when a decision changes)
Resolve high-severity findings before planning implementation.
4

Implementation Plan

planner

Creates prioritized, dependency-ordered tasks with requirement links, completion criteria, and explicit blockers.

  • impl-plan.md
Plan must be approved and unblocked before implementation.
5

Implementation

implementation-agent

Implements approved tasks in small increments, validates inputs, handles expected failures, and keeps requirements traceable.

  • Source files changed by approved tasks
  • Implementation notes when required
No persistence or schema work without approved requirements.
6

Verification

test-generator
deployment-agent

Creates focused unit and integration coverage, then validates relevant lint, security, test, coverage, metadata, and content-quality gates.

  • Test files
  • Verification evidence
  • CI/CD evidence
Fix failing checks; do not bypass them.
7

Code Review

code-reviewer

Reviews correctness, security, errors, tests, clarity, duplication, dependency safety, and documentation metadata.

  • Review findings and remediation evidence
All blocking review findings must be resolved or formally accepted.
8

Pull Request

pr-description-agent

Assembles an evidence-based pull request only after verification and review are satisfactory.

  • PR description
  • Changelog entry when required
Human review approval required before merge.

Always On Guardrails

Safety Guard

Blocks destructive requests, credential exposure, security disabling, test skipping, and force pushes to protected branches.

Quality Gates

Linting, security scans, tests, coverage, documentation front matter, and peer review cannot be bypassed.

Protected Branches

Use feature branches and reviewed pull requests. Direct or forced pushes to main and master are not allowed.
